## Outcome
Enforce permissions in services/kernel with a verifiable manual control path.

**Plan:** #1 · **Milestone:** H1 · **Type:** Implementation
**Hard dependencies:** #5, #6, #11, #12, #45.

## Deliverables
- [x] Minimal service supervisor with queryable identities, dependencies, state, and failures.
- [x] Initial owner authority path and authenticated IPC; granting, restriction, expiration, and revocation of capabilities or the chosen mechanism.
- [ ] Enforce authority on open resources, explicitly provisioned helpers in the same session, devices, and effects; persist owner policy and recover manually.
- [x] Native deterministic clients using #11 to test authority bootstrapping and prevent a service from amplifying the requester's permissions.

## Acceptance tests
- [x] Keep independent owner queries, session revocation, actor status and non-file utility control responsive during a stopped file service; distinguish missing from late acknowledgments and prove explicit restart recovery before device admission.
- [x] Keep foreground file waits interruptible and supervisor provisioning/restart nonblocking; retain a retiring service while an actual submitted write drains, with queryable progress and recovered effect evidence.
- [x] Allow granted operations and deny direct/indirect out-of-scope access on the implemented native file surface.
- [ ] Revoke and check new actions, handles, and descendants according to the contract; document effects already underway.
- [x] Restart services without inheriting incorrect authority and recover policy without AI.

## Scope and limitations
No model, GUI, or MCP required. The mode/confirmation interface is in #24; final adversarial tests are in #28.

## Closure
Link the implementation or decision, configuration/versions, tests, and evidence; record the review and limitations in accordance with #1. Checkboxes remain pending until those results are available.

## SDK integration boundary — 2026-09-10
The [SDK/manifest contract](https://github.com/alseif0x/rustic-os/blob/9208ae50cd069832279df76ba8e041ecac86f5da/docs/SDK.md) provides native entry, identity queries, IPC clients and strict application admission. Manifest identity/version are descriptive metadata, not an authenticated principal. Capability bits express required features and never grant endpoint authority; the current launcher provisions handles separately.

Bind service identity and grants to trusted supervisor state, enforce resource scopes on each operation, and test restart/revocation without inheriting old authority. Extend the manifest schema explicitly if persisted policy needs richer requests; do not reinterpret schema 1 bits or a model-supplied identity as an authorization token. Diagnostic REPORT remains a bounded ambient syscall in ABI 1.0, not evidence of per-application permission enforcement.
