Updated 2026-09-15. Replace this checkpoint rather than appending conversation history.

## Direction and current increment

Own modular Rust OS; isolated native applications, human and agent clients sharing authority and semantics. MCP is optional. Multiple preempted processes currently execute on one CPU; SMP, independent application installation and physical-machine support remain unimplemented. [Issue #1](https://github.com/alseif0x/rustic-os/issues/1) and the [systems roadmap](architecture/systems-roadmap.md) own sequencing.

Current increment over `e17f6b4` (uncommitted working tree on `main`): **#49 completed with a product consumer and shell-observable exhaustion**. The `TASKS_OWNER` child in `apps/utility` keeps its candidate bytes in one SDK `Heap` page reserved at the first `TASKS_EDIT`/`TASKS_BEGIN` of a plan and released when the apply concludes or the state clears (`apps/utility/src/tasks/{state,owner}.rs`, borrowed-storage `Candidate<'a>`/`CandidateBuilder<'a>` in `crates/tasks-client`, code `106` for a memory refusal); `act PID tasks-heap-stress` (actor 31, TASKS_OWNER only) grows a private heap to the budget, releases it and reports `[error, peak, full, pages_after_release, limit]`; the supervisor forwards `INFO` word 7 and the shell `mem` line ends with `heap_pages=`; the supervisor's actor admission predicates live in its library with host tests, and the shell acceptance lifecycle cases compare heap pages before and after.

Previous increment `e17f6b4`: **dynamic user memory with a bounded native SDK allocator** for [#49](https://github.com/alseif0x/rustic-os/issues/49). Three ordinary process syscalls in `crates/abi/src/memory.rs` (`MAP` 21, `UNMAP` 22, `QUERY` 23) map zeroed, never-executable pages inside a per-process heap window (`0x1000_0000`, 128 pages, 64-page budget) whose reservation lives in the pure `kernel/src/process/heap.rs` bitmap; `map_user_pages`/`unmap_user_pages` sit over the existing zeroed mapping primitives with multi-page rollback, ELF segments may not reach the window, reap reclaims through the existing `destroy_user`, and `INFO` word 7 sums heap pages of unreaped processes. The SDK adds `memory::{raw, allocator, Heap}`: typed syscalls, a first-fit allocator with in-region three-word headers, coalescing, generation-tagged handles and exact accounting (`Region` is its only `unsafe`), and a `Heap` that grows and shrinks by whole pages; no `GlobalAlloc`. The consumer is `apps/sdk-probe` under the kernel `ok` fixture. [Process ABI](PROCESS-ABI.md), [Memory](MEMORY.md) and [SDK](SDK.md) document the contract and limits.

Earlier increment `4458b73`: the second native semantic tasks client (`apps/utility` under `TASKS_OWNER` over `crates/tasks-client`, two-scope grants, deterministic cuts) with its guest suites `tools/tasks_owner_test.py`, the `tasks.owner` phase of `tools/terminal_test.py` and `tools/tasks_owner_normal_test.py`; see [Tasks](TASKS.md) and [Authority](AUTHORITY.md).
